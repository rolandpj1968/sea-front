# Tests that sea-front is not expected to pass on the g++.dg suite.
#
# Format: one relative path per line (relative to SEA_GCC_TESTSUITE root).
# Lines starting with '#' are comments. Trailing whitespace ignored.
#
# When a listed test is run:
#   - non-PASS outcome → XFAIL (expected fail, doesn't pollute the FAIL/E_*
#     buckets and signal real regressions)
#   - PASS outcome      → XPASS (loud — likely the test deserves removal
#     from this list because some other slice fixed it)
#
# Buckets recognised below:

# --- Itanium C++ ABI conformance ----------------------------------------
# Sea-front uses a deliberately-private object layout, vtable shape, and
# EH model — see docs/mangling.md "System-class interop" and docs/rtti.md
# for the rationale. These tests assert specific gcc-on-ilp32 layout
# offsets that sea-front isn't aiming to match.

# --- Out-of-scope C++11 features ----------------------------------------
# These need substantial C++11 work that sea-front hasn't built out yet.
# Listed here so the FAIL count tracks real regressions rather than
# known deferred slices.

# implicit2 needs:
#   - Synth copy ctor SYNTHESIS (sea-front emits only default ctors when
#     no user copy ctor is declared; the test relies on C's synth copy
#     ctor calling A's chosen copy ctor on the base subobject).
#   - Function-template overload resolution: A has both `A(const A&)`
#     and `template<class T> A(T& t)`; for a non-const A& source the
#     template wins (better match than the implicit const conversion),
#     so the template body runs. Sea-front's overload resolver doesn't
#     consider template ctors yet.
#   - Template-ctor MANGLING (`_ZN1AC1IS_EERT_`) + body instantiation
#     with T substituted to A.
# Together these are multi-week work; deferred until the C++11 sweep.
g++.dg/cpp0x/implicit2.C

# --- Universally xfail in gcc itself ------------------------------------
# These tests are marked `dg-do run { xfail *-*-* }` in the source — gcc
# itself expects them to FAIL on every target. Listing here surfaces
# that signal in the runner's bucket counts. Only include tests where we
# also fail; tests where we PASS something gcc-xfails are surprising
# good news and stay in the PASS bucket.

# --- AddressSanitizer test using dg-shouldfail --------------------------
# The test deliberately triggers a memory error and expects ASan to
# catch it; gcc honours `dg-shouldfail "asan"` and treats the non-zero
# exit as PASS. Our runner only checks exit==0, so the test reports
# FAIL even though sea-front does what it can (it doesn't have ASan).
g++.dg/asan/function-argument-2.C

# --- Signal-driven / forced unwinding EH --------------------------------
# Tests in this bucket install a signal handler that throws a C++
# exception, or call _Unwind_RaiseException directly, or rely on
# -fnon-call-exceptions to turn synchronous CPU traps into throws.
# Sea-front's TLS-polling EH design (see docs/exceptions.md) is
# fundamentally synchronous — exceptions can only originate from a
# `throw` statement in code sea-front emitted. There is no mechanism
# to convert a signal or a CPU trap into a polled exception state.
# These tests cannot pass under the current EH design.
